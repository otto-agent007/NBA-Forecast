# Daily forecast review

The requested review covers every game on a Pacific calendar date, reconciled
final results, original preliminary and final forecasts, and concrete questions
that can improve future forecasts. Extend the existing runner and Performance
view. Reuse final-cache validation and the existing postgame error decomposition.

Choose a deterministic daily report over a paid narrative service or an automatic
parameter optimizer: the existing evidence is sufficient for transparent errors
and review priorities, while one day is insufficient to tune model constants.
This implementation choice follows the user's request to review the completed
day and the established automatic operations workflow.

Select the latest eligible live league run per game/stage before loading outcomes.
Verify hashes, real creation/cutoff times, season, teams and scheduled tipoff.
Never substitute an older numeric prediction for a newer abstention. Summarize
projected-player results separately from out-player zeros, missing/withheld rows,
and incomplete team totals. Preserve the original model versions. Partial totals
and overtime must be explicit. Compare stages on identical projected player pairs.

Every date report contains coverage, each game's score and totals, stage metrics,
player errors and accounting decomposition, major role/status/attempt misses,
evidence-linked improvement questions and unavailable detail. Full play-by-play
is optional for boxscore comparison; absent evidence cannot establish foul,
injury, blowout or coaching causes. Original forecasts remain immutable.

Build today's and yesterday's reports after result collection, using signatures
to avoid rewriting unchanged reviews. The dashboard displays the selected date
and links its game and player evidence. Missing finals stay visible and retryable.
New actuals enter the existing history and calibration pathways automatically;
new model changes require multi-game evidence and validation.
